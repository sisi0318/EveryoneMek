# Overload Core · 过载短路核心

**0.1.0-alpha.30** · Minecraft 1.21.1 · NeoForge 21.1.241 · Java 21

一枚以雷霆为食的科技挂坠。缔结魂契后，八道禁律缠上你与麾下机枢，也赐予逆铸、回能和洞察之力。

> 以此残躯，续接神明断裂的回路。

## 安装

客户端与服务端都安装本模组、**Mekanism 1.21.1-10.7.19.85** 和 **Curios 9.5.1+1.21.1**。Mekanism Generators 为可选依赖，使用同一 Mek 版本。其他 EveryoneMek 扩展不是依赖。

本地构建产物：`build/libs/OverloadCore-0.1.0-alpha.30.jar`。客户端与服务端需一起更新。

alpha.18 修复武器、雷印电容和改装页的储能文本显示。若旧版出现 `EnergyDisplay@...` 跳动，那是对象标识被误显示，实际电量不受影响。

alpha.19 移除独立饰品页面和过载核心升级；已有核心储能保留，旧版已安装模块返还一次。

## 黑洞发射器

独立储能武器 `overloadcore:black_hole_launcher`，可在本模组创造栏找到或通过 JEI 查看合成。放入 **Mek 能量立方的充电槽**补充电量，也支持 MekaSuit 背包充电和 FE 充电设备。

- **按住右键2秒，松开发射**；屏幕进度条提示就绪。提前松手、换掉物品或电量不足不会发射。
- 储能 **10,000,000 FE**，每发 **250,000 FE**；不用弹药。支持副手。
- 奇点命中方块／有效目标，或飞行48格后展开；牵引6格内可见目标，默认每0.5秒造成4点基础伤害，持续5秒。
- 发射恢复时间5秒，每位玩家同时只能维持一个黑洞。不会伤害或牵引使用者、队友、创造玩家和受PVP规则保护的玩家；方块遮挡引力与伤害，保留方块和掉落物。
- 展开后的黑色核心半径3格、直径6格，约为alpha.29的2.6倍；飞行奇点大小不变。立体白金吸积盘保持空间朝向，以明暗分明的发光气流、贴近核心的亮环与上下弯曲光弧表现；背景透镜仍检查前景深度。视觉放大不改变伤害或牵引范围。
- `blackHoleLensing=false` 可关闭背景透镜，保留三维核心和流动光盘；`weaponShaders=false` 使用简化几何。多黑洞时最近8个显示透镜，其他保留三维外观。实际游戏画面及第三方光影组合由玩家验收。

服务器配置 `combat.blackHoleShotFE`、`blackHoleChargeTicks`、`blackHoleCooldownTicks`、`blackHoleLifetimeTicks`、`blackHoleRadius`、`blackHoleDamagePerPulse` 调整数值。离线或跨维度时清除自己的黑洞，区块卸载也不会留下持久化引力场。

## MekaTool 战斗双形态

在 **Mek 原版改造站**给 MekaTool 安装一个“战斗形态单元”，使用 Mek 的物品模式键／径向菜单选择近战或远程，也可在原模块配置窗口切换。

- **近战形态**：普通攻击沿用 MekaTool 原有攻击增幅；按住右键蓄力，松开向准星方向斩出一道两端收尖的剑气。
- **远程形态**：按住右键蓄力，松开发射磁轨脉冲，只消耗电量。
- **采掘与工具操作**：采掘照常；潜行右键保留原工具动作，包括已启用的传送功能。
- 储能、充电、能量升级和基础外观全部沿用原 MekaTool。形态显示在原 HUD／物品提示中，工具头部以局部 shader 刃沿或聚焦环区分。
- 充能加速、磁轨复位、聚焦、贯穿、刃场扩展与谐振模块均安装到原 MekaTool；完整数值见[装备模块说明](GEAR_EXPANSION.md)。

**独立雷铸刃与磁轨长枪已移除**：没有合成、创造栏入口或自绘模型。已有物品进入玩家背包／副手后转换为对应形态的 MekaTool，保留模块、名称和电量；暂时超过原生容量的旧电量随消耗逐步转入。

alpha.23 取消弹药与装填。原弹仓单元改为磁轨复位单元，保留已安装等级，每级减少0.1秒射击恢复时间。alpha.25 将飞出的弧形斩击改为斜向剑气，带短暂渐隐尾迹；工具头保留弧形接触刃。

## 战术模块与全息靶场

- **R：形态快切**。手持已启用战斗模块的 MekaTool，直接切换近战／远程；主手未装备时支持副手，切换会取消当前蓄力。原模式菜单继续可用。
- **极化联动单元**装在 MekaTool，最多3个。有效远程命中叠加极化，蓄力斩击消耗标记增加伤害；有效近战命中敌人后，下一发磁轨脉冲额外贯穿一个目标。
- **磁偏护盾单元**装在 MekaSuit 胸甲，按住 **Z** 展开前向护盾，松开收起。持续与拦截都消耗胸甲电量；开启后的短窗口精准格挡可强化下一次蓄力攻击，支持原版箭／光灵箭反弹。
- **全息靶场控制器**可直接接 Mek 能量立方或电缆。右键打开原生风格界面，开启投影后攻击训练靶，可查看本次／累计伤害、命中次数、近5秒DPS和工具耗能。上方需留两格空气；断电或拆除控制器会收起投影。

投影带有人形轮廓、胸前靶心和底部投射环。有效命中会短暂亮起、显示伤害浮字并发出轻提示音；同一刻的多段伤害合并显示。近距离用准星指向训练靶可直接查看本次伤害和DPS。控制界面将状态、伤害／DPS与累计统计分区显示，重置后同步清除旧反馈。

alpha.27 修复头顶浮字偶尔只剩背景、没有文字的问题，浮字改用文字阴影，仍会被墙体遮挡。

键位可在游戏控制设置中修改，工具提示显示实际绑定。训练投影不提供经验／掉落，也不提供可带走的贯穿增益。详细规则见[装备模块说明](GEAR_EXPANSION.md)。

## 饰品与防具升级

MekaSuit 使用原生改造站安装模块。逆命雷印先正常摘下，放入原改造站的装备槽，改装后重新佩戴。过载核心不需要升级。

## 余雷耦合单元

首个 Mek 原生装备升级，安装在 **MekaSuit 胸甲**，最多 4 个。通过原生改装站安装／拆卸，在 Mek 模块配置界面开启或关闭；无需新机器或额外快捷键。

佩戴过载短路核心和装有模块的胸甲后，回收的“余雷”优先送入胸甲。四级默认上限分别为 **4,000／16,000／64,000／256,000 FE/t**，受实际余雷存量、胸甲空间与原生接收速率限制。核心缓冲默认为 100,000 FE，不再通过模块扩容，升级提高的是转移上限，不产生电量或提高回收比例；需要持续的机器额外电耗才能持续补充余雷。

胸甲装上 Mek 的**充电分配单元**并开启其中的**背包充电**后，可继续给工具与支持充电的饰品供电。余雷耦合本身不重复执行这一分配。胸甲满时，剩余电量可按原来的普通充能上限供给随身装备；全部满电则留在核心。关闭模块、脱下胸甲或把它放在背包中，只保留原本的基础充能效果。

合成为 4 个强化合金、2 块能量板、2 个高级控制电路和 1 个模块基板；可用 JEI 查配方。模块使用 Mek 原生基板与原创绿色耦合图案，原生物品提示显示支持装备和安装上限。

服务器配置 `equipment.couplingFEPerTickLevel1` 至 `Level4` 调整四级上限，实际取已安装等级中的最高值且不低于基础充能上限。基础充能支持清单为物品标签 `overloadcore:recovery_chargeable`，默认包括原版 MekaTool 和四件 MekaSuit；额外物品还需提供可接收的能量接口。模块的高速路径只向实际穿戴且启用该模块的胸甲供能。

## 逆命雷印

> 借万机一瞬之雷，驳回此身既定之死。

新增护命饰品 `overloadcore:thunder_ward`，右键佩戴或直接放进“护命”栏位，可自由摘下，也可与过载短路核心同时佩戴；不需要先绑定过载核心。按住 Shift 可逐行查看说明。图案参考 MekaSuit 的装备风格，采用深灰底层、银灰分块护板、绿色能源核心和外围白绿雷弧。佩戴时显示在右前臂，触发时保留电火花、音效和简短状态提示；雷印不会在屏幕中央弹出图腾式动画。

佩戴后，雷印抵抗强行卸下、清空槽位、改数量和改物品数据；槽位或饰品数据被绕过接口删除时，按独立保存的记录恢复。死亡后仍随身，修复饰品本身不耗电。正常点击摘下、Shift 移入背包、数字键换位和在饰品槽主动丢弃照常；成功摘下后停止防丢，也不再保命。需要改名或修改附魔时，先正常摘下。模块改装需先正常摘下，放入原版改造站；重新佩戴时登记改装后的完整物品。佩戴中的正常充放电会合法更新保护记录。更新前已佩戴的雷印会自动建立保护记录，无须重做。

- 受到致命伤害时，从同维度 **32 格**内自有或明确授权的设备合计抽取 **100,000 FE**，保留 **1 点生命（半颗心）**。
- **不设冷却**。没有次数盾挡下的独立致命伤害可以立即再次触发，每次重新付费。
- 成功保命后获得“余雷护身”：默认挡下后续 **3 次伤害，最多持续 3 秒**。不额外扣电，不叠加次数；用完或到期后恢复正常受伤。主动摘下、退出或换维度会清除剩余护盾。
- 默认按 **V** 切换极限抽能，可在按键设置中修改。普通模式默认给每个供能容器保留容量的 **10%**；极限模式可动用留存电量，但每次仍只抽取所需的 100,000 FE。模式由服务器确认，重登后保留。
- 先核对总电量，再由非空储能按比例分摊；电量不足时不扣除部分电量，也不阻止死亡。能量单位采用 Mek 的实际 FE/J 换算。
- 支持 Mek 机器、能量立方、已成型感应矩阵，以及复用 Mek 基础储能容器的扩展机器。电缆共享网络、孤立感应元件及其他模组仅提供通用 FE 接口的设备，不作为当前供能源。不会沿电缆抽走远处或其他所有者的电量。
- 矩阵多个端口只计一份储能，内部元件不重复计数；矩阵按原生提取队列和供能吞吐结算。当次输出余量不足的部分不算可用电量。
- 已有次数盾先挡伤害；没有次数盾时，原版图腾仍先于付费保命。图腾已经救下玩家时，雷印不收费。普通非致命伤害不会触发新的扣电或护盾，治疗、退出和换维度也不收费。

合成为原子合金、终极控制电路、两块能量板、下界之星和回响碎片。服务器可通过 `wardCostFE` 调整每次消耗，范围沿用 `range`；`wardReservePercent`、`wardShieldHits`、`wardShieldTicks` 分别调整默认留电比例、次数和持续 tick 数。`wardShieldHits=0` 可关闭次数盾。

左下角显示当前抽能模式；有护盾时显示剩余次数和时间。`/overloadcore ward status` 查看最近触发结果、最近扣电量及供能数量。失败时区分没有可用设备、电量/输出不足和留电限制。

对准自己的机器可设置供能，已成型矩阵按整座结构设置；极限模式也不能突破禁止供能或所有权限制：

- `/overloadcore ward source false` 禁止这台设备供能，`true` 恢复。
- `/overloadcore ward reserve <0–100>` 设置这台设备的普通模式留电比例。
- `/overloadcore ward share <玩家>` 单独授权救命抽电；`unshare` 撤销。
- 新的过载核心 `share` 不再自动授予雷印抽电权限。旧版已有明确共享名单保留，Public 安全模式不算授权。

若回档或迁移后显示“雷印待核验”，物品会保留并暂停生效，不再因记录缺失直接删除。管理员可用 `/overloadcore ward inspect <玩家>` 检查，`repair <玩家>` 核验护命槽或玩家主手里的原件；被占用或已解除的旧标识拒绝重新授权。`release <玩家>` 正常解除保护并返还原件，不清空玩家库存。仅这些管理操作要求管理员权限。

抵抗覆盖正常致命伤、`/kill`、直接清血、`die()`、破坏性移除，以及绕过这些入口的同步生命值写入、在线 NBT、死亡计时/标记篡改、异常最大生命和底层实体管理器移除。探针会核对真实数据并付费修复。次数盾处理实际伤害结算；直接改血和移除仍走付费保护。没有护盾时保留原版图腾优先，雷印随后在 `die()` 正文前拦截，会早于普通死亡事件监听器。

同一 tick 内一串清血/死亡/移除调用按一次致死过程防重；新的 `hurt()` 调用仍开启新的付费判定。正常退出、传送和重生放行。已完成死亡会持久记录结算标记，防止丢弃临时状态或重载后又被回拉；原版正式重生开启新生命。

保命仍需要供能范围内足够的电。例如虚空伤害类型已覆盖，但真的跌离所有机器后不会凭空获得电量。雷印自身的恢复不会返还其他被删除的库存，也不能保证抵抗重写本模组、同时破坏独立存档或伪装正常操作的代码。截图中未公开的 `SwordUtil.annihilate`、`TranscendUnsafeKill` 内部实现未得到完整验证。具体层级见 [1.21.1 抵抗层级研究](DEATH_PROTECTION.md)。

## 装备与操作

- 核心使用专用的 `overload_core` 饰品槽，空栏位显示灰色吊坠轮廓，悬停名称为“核心”，不会覆盖其他模组的普通饰品槽。
- **手持核心，按住右键两秒**完成绑定。捡起物品、放进背包或尝试直接拖入槽位，不会自动装备。
- 生存模式无法主动卸下，死亡仍保留。绑定记录、实例 ID 和回收电量随玩家保存；异常移除后尝试恢复同一件核心，并清理重复实例。
- **鼠标悬停挂坠**，风味文字显示为亮色斜体，带红蓝错位叠影和轻微抖动。
- **按住 Shift**，每隔 0.16 秒显示下一行，约两秒展开完整说明。说明也带红蓝色散，新行保留短暂打字机光标和扫描提亮；已显示的内容不会循环消失。诅咒主字为红色，收益主字为绿色；自己的已佩戴挂坠还显示回收电量。松开 Shift、移开鼠标或换到另一栏位后重置，再次查看从第一行开始。
- 左下角为半透明的双条状态面板：**磁枷**显示金属负荷／禁跑阈值，临近阈值变为琥珀色，已被禁跑时为红色；**劫热**显示体热百分比，高热时转红。负荷以锭当量计，阈值采用服务器配置。打开菜单时隐藏面板，F1 同样可以隐藏。
- 挂坠以“熔魂契印”“雷饕之心”“逆铸天工”等契文描述代价与赐福；“余雷”为实际回收电量，单位仍为 FE。具体规则与支持范围见下表。
- **K** 切换附近设备的位置、工作状态和热源提示，潜行＋K 也可使用。没有独立说明窗口或翻页操作。`/overloadcore info` 在聊天栏报告当前回收电量、金属负载和体热。
- 管理员可用 `/overloadcore clear <玩家>` 清除绑定并移除已装备实例。创造模式正常卸下可解除绑定。生存模式没有解咒合成。

合成材料为强化合金、精英控制电路、两块能量板、下界之星和钢锭。也可由整合包修改配方或作为自选挑战奖励。

## 作用范围与共享

机器效果只作用于同维度 **32 格**内的自有或明确授权设备。多人覆盖不会再乘一层倍率；回收电能优先分给最近的有效佩戴者。

Mek 自带的所有者记录优先；没有这类记录的管道会记录放置者。多方块需要各部分有一致的已知归属，混合或未知归属不自动受影响。不会把 Public 安全模式当作其他人同意接受诅咒。

对准自有设备，使用 `/overloadcore share <玩家>` 授权，`/overloadcore unshare <玩家>` 撤销。旧管道、已有多方块或不明确的归属可由管理员对准设备使用 `/overloadcore claim` 登记。多方块按最近结构外表面计算距离，整个结构只结算一次。

| 漏电排斥 | 贴近实际工作设备时先出现电火花，继续逗留会受伤和击退；每人有独立冷却。 |
| 总线拥塞 | 适用管道的主动拉取限额减半，网络对受影响端点使用半额交付预算；反复分配不再增加同 tick 预算。物品在符合归属条件的运输管中移动变慢。 |
| 电磁耳鸣 | 原机器声音对佩戴者放大，近距离持续暴露会反胃；消声升级按当前 Mek 的实际最大数量生效。 |
| 磁性重载 | 默认 384 锭当量时禁跑，降到 352 以下恢复。计算随身物品、护甲、饰品及有原版容器组件的内容，不读取远端 ME/QIO 网络。 |
| 热失衡 | 实际热容和活动中的冶炼设备产生热暴露，体热积满后持续受伤；离开热区或入水可降温。原防护和原辐射机制继续按 Mek 处理。 |

- **极限良率**：指定配方主产物翻倍。矿物入口加成，后续中间步骤不再次加成；基础元件包括初级控制电路和基础合金。
- **漏电回收**：实际额外电耗的 25%进入核心缓冲，再给随身 MekaTool、MekaSuit 充能。内部用 Mek 原生能量单位计量，避免来回转换 FE 的取整增殖。
- **机具共振**：有电且正常发挥挖掘能力的 MekaTool 挖掘效率提高 25%。
- **工况感知**：查看附近授权设备的位置、加工故障和热源。原机器面板中的额定参数不作为诅咒后的实时功率显示，实际扣能、产电和核心倍率才是结算依据。

## 增产与物流边界

首版包含 **68 条已核对的默认配方定义**。运行配方必须与随包记录的定义一致才可增产；任意数据包改写同 ID 的原料、产量或耗材不会自动继承奖励。标签被整合包重新定义时仍需要额外审核，不能据此保证所有整合包绝无循环。

富集、提纯、压射和溶解的指定铁、金、铜、锇、锡、铅矿物入口，以及基础元件可获益。粉锭往返、压块拆块、后续矿物工序、核燃料／废料和任意自动合成不在默认名单。溶解粗矿块的翻倍量超过原输出罐容量，因此不列入增产范围；它照常加工。

一批加工从开始起必须连续按诅咒工作费率推进。临近完成才靠近不会拿到整批奖励；某个有效步骤按普通费率推进后，该批只产出原数量。没有双份输出空间时先等待，不先扣料再积压一份无限期奖励。

管道保留原容量与已有物资。物品五节路径的耗时接近原来的两倍，不逐节乘成三十二倍。液体、Chemical 和能量按原生拉取／分配方式限制；缓冲、低负载和多个端点会影响瞬时读数，不以删掉一半物资实现“减速”。未授权设备不被整网强制降速。

**反应堆冷却可能受到真实的物流限制。**核电安全回路建议与检修作业区隔离，不要只依据原来的刚好够用流量布置。核心不主动加热反应堆或产生辐射，但也不能保证被限流的冷却系统仍安全。

热力导管的传热、量子传送、AE/QIO 物流、其他科技模组和不使用上述工作容器的特殊设备，不在首版通用适配范围。物品运输的最终结果由服务端决定，客户端插值、声音、饰品位置和界面体验需要游戏内验收。

## 配置与开发

服务器配置提供范围、金属阈值、回收缓冲、充电限速、声音倍率，以及工作／发电／运输／作业危险开关。经济倍率为本版固定的双倍工作耗电、半发电与双倍受控产物。改变缓冲上限不会删除已有电量。

构建使用本目录 Gradle Wrapper、Java 21 和独立 `.gradle-home`：

```powershell
$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-home'
.\gradlew.bat build runGameTestServer
```

`-PwithGenerators=false` 可验证不安装 Generators 的环境。服务端测试不包含在发布 JAR 中。客户端游戏内验收由用户进行，不自动运行客户端。
