# 微缩太阳 · 追加设计候选

2026-09-24。用户询问还能补充哪些设计。下方是经过筛选的建议，**尚未由用户逐项确认，也没有实现**。长效燃料、9格结构和高功率基准继续见 [主设计](SOLAR_DESIGN.md)，本轮不再提高基础数值。

## 建议顺序

| 建议 | 玩家得到什么 | 建议阶段 |
| --- | --- | --- |
| 按需调载 | 用多少补多少，少浪费燃料和手动开关 | 首版优先 |
| 剩余燃料回收 | 已燃烧一部分的恒星燃料还能搬走继续用 | 首版优先 |
| 限速诊断与告警 | 看得懂没满功率的原因，可以自动提醒补货 | 首版优先 |
| 发电量可见、亮度可调 | 从太阳和采能翼就能看出状态，近看不刺眼 | 首版优先 |
| 耀斑升载 | 工厂突然满载时短时提高发电，额外消耗燃料 | 首版后增强 |
| 日冕加工仓 | 分流一部分采能，用太阳制造后期材料 | 独立扩展 |
| 整组升级与配置复制 | 升级采能翼时少跑腿、少重复配置 | 首版后增强 |

前四项围绕长时间自动运行；耀斑和加工仓增加可选择的玩法。首版仍只需要主设计中的一份长效燃料，不把这些候选变成新的强制维护条件。

## 1. 按需调载

提供“自动调载”和“手动负载”两种模式，默认自动。自动模式仍遵守玩家设置的最大负载。

- 使用本机可用缓存比例，扣除保护备用电后计算。默认低于25%恢复补能、高于80%进入保能/待机区，两个阈值分开，避免临界点反复点火。
- 运行期间根据最近20tick的真实输出，以及内部加工请求，平滑调整补能功率。输出满额时提高负载，外部不收电时降低负载；100%满缓存立即停耗料，不能等平滑动画完成。
- 待机只是停止推进反应，点火资格和当前燃料预算保留。自动续料关闭时，已投入燃料可以继续反应，耗尽后不再取下一份。
- 多台太阳可分别选主供电/备用角色。首版只提供不同阈值预设，不扫描或接管别人的电网；跨机器集中调度另做明确连接的扩展。

这里没有“自动知道AE网络/远处感应矩阵的电量”。没有接入专门遥测时，只能依据本机缓存和实际接收量判断。外部拒绝接收时应写“外部暂不接收电力”，不能武断显示“整个电网已充满”。

## 2. 剩余燃料回收

停机后点击“回收燃料”，将当前未用完的反应预算封装成一个**残余恒星燃料胶囊**。提示显示剩余百分比和能量，再次投入后接着使用。

- 胶囊为原燃料的带数据形式，最大堆叠1；保存原燃料标识、原总预算、剩余J。不能按新配方或初始寿命重新算满。
- 不携带点火资格、机器所有权或主控设置；给另一台尚未点火的太阳使用时，仍需按该装置自己的启动条件运行。
- 回收前检查停机状态、输出槽和权限。只有胶囊可被实际接收时才扣除主控对应预算；满槽、取消或失去权限都原样保留。
- 再投入时，先预检剩余能量合法性和装置容量，再原子地扣胶囊/增加预算。客户端只能发操作请求，不能上传任意剩余能量。
- 普通GUI、自动化提取及两个玩家同时操作共享同一服务端事务。不能出现胶囊已拿走而机器还能继续使用同一份燃料。
- 现有主控拆卸时保存未用预算的行为保留；已经回收进胶囊的部分不得再写入主控掉落物。

回收不是额外产物，不引入必须定期清理的灰烬或废料。无需为了换基地而舍弃一份尚余十几小时的燃料。

## 3. 限速诊断和告警

主界面保留简洁数字，详细限制放在“供能情况”侧栏。一次指出当前起主要作用的限制，而不是只显示泛泛的“效率不足”。

可报告：

- “约束环限制：512 GFE/t，升级约束环可提高上限。”
- “采能翼未跟上：目前四翼合计1.024 TFE/t。”
- “输出接口达到上限”“外部暂不接收电力”。
- “等待下一份燃料”“自动续料已关闭”。

每个输出口显示当前模式、最近平均输出、本口额度；能量流速用短时平均，避免单tick波动让数字不停跳。装置总吞吐仍以实际预算为准，不把每个口显示值再乘方块数量。

补充“燃料不足”和“结构异常”红石告警。只在专门的信号面输出，阈值和信号用途可选，不能影响原有红石启停输入。缺料告警初值建议“没有可用备用燃料，且当前这份按当前负载不足15分钟”；停机时不预测倒计时，可改看剩余比例。

预计时长区分：本份剩余、仓内备用数量。大库存累计能量可能超过long，不将几十份预算直接相加写回主控；需要总时长时按燃料组计算，显示端使用足够精度并允许“超过N小时”，服务端加工仍仅持有当前预算。

可选后续增加CC:Tweaked监控：读运行状态、当前燃料、净发电、实际输出和各翼等级，用来搭建控制室大屏。先做只读能力，远程启停/负载修改需沿用本模组安全权限；卸载区块时报告不可用，不强制加载。数值精确接口用十进制字符串，便于大预算传输时避免脚本数字精度损失。此处仅为接口方向，未声明已经兼容。

## 4. 让工作状态从外观就看得出来

- 开机后采能翼机械展开，内侧灯依次点亮；顺序只影响动画，不逐段扣费或延迟解锁已经可用的端口。
- 自动待机时采能翼稍微合拢，太阳缩为赤红余辉；恢复需求后重新展开，不重复点火。
- 正常工作时，每组采能翼的光带强度对应其实际份额；输出口有短促的外流光线，堵塞的口不冒“假装有电在输出”的光点。
- 补下一份燃料时只做一次温和的核心脉冲，不重演整段点火，也不跳出图腾式特效。
- 提供客户端亮度与特效密度设置。降低眩光后保留表面暗纹、轮廓和采能翼细节；只影响本人画面，不改变发电、判定或其他玩家设置。

首版不加真实星体引力、吸物品、燃烧周围方块或无提示的照射伤害。太阳可以有压迫感，但常规自动化不需要额外穿防具、补耗材来免受随机惩罚。

## 5. 耀斑升载

现有设计已经允许缓存按接口上限快速输出，再增加一个更低速的“缓存放电按钮”属于重复功能。因此建议的耀斑是**可选的短时提高反应功率**，带额外燃料成本；平时基础功率、现有缓存放电和每份燃料能量都不变。

由后续“耀斑调制器”模块解锁，不是首版基础机器的常驻额外倍率。候选初值：反应功率临时提高至当前约束/采能配置额定上限的125%，最长30秒；该段每单位毛发电额外消耗15%燃料能量，结束后至少60秒恢复。玩家手动或由后续受权限约束的指令触发，默认不随机出现。

以终极配置、当前装置能持续正常发电且外部全额接收为例：

| 项目 | 数值 |
| --- | ---: |
| 正常净发电 | 1.9456 TFE/t |
| 耀斑毛发电 / 净发电 | 2.56 / 2.432 TFE/t |
| 每tick实际扣燃料预算 | 7.36 TJ，比正常5.12 TJ提高43.75% |
| 满额30秒总燃料消耗 | 4.416 PJ，比正常多1.344 PJ |
| 满额30秒额外净发电 | 291.84 TFE |
| 需要的1.024 TFE/t输出口 | 至少3个 |

燃料扣除中同时覆盖电能、5%约束自耗及额外升载损耗。不能另外生成一份“可回收耀斑热量”再发一次电。燃料不足、缓存满或结构失效立即提前结束，不承诺一定持续30秒，也不允许负预算。

触发前检查模块、成型、已点火、剩余燃料、缓存空间和实际出口能力。输出口仍按真实接收量扣缓存；反应按真实新增毛能量扣燃料。接收器限速时可以使用剩余缓存空间缓冲，满后结束，不能绕过FE分批计算预算或开关模式刷新端口额度。

耀斑时日冕稍微扩张、日珥更明显，采能流短时变粗；不用白屏闪光或地形爆炸。剩余时长与冷却保存，重开GUI、重载或拆装不能重置；离线不结算发电和放电。

## 6. 日冕加工仓

作为后续可选模块，允许把部分采能用于制造**恒星合金**等后期材料，让太阳拥有发电之外的用途。

建议初版扩展只做一种明确用途：原子合金、锇/精炼黑曜石等材料在日冕加工仓中加工成恒星合金，供更高阶采能翼与后续扩展使用。首台初级太阳及首台加工仓的合成不能要求恒星合金，避免解锁循环。

加工仓需要接入已形成且具备燃料预算的太阳，材料和产物使用本仓真实槽位；不能让旁边随便放一个机器就凭距离无限获得“太阳加成”。一仓只属于一台太阳。

供能规则：

- 同一太阳所有加工仓合计最多分配净采能的20%，这个比例可配置；不能每个仓各获得20%而无限叠加。
- 加工耗能从主控同一实际电缓存扣除，默认优先保障外供，余量用于加工；GUI显示“外供”和“日冕加工”各自占用。
- 加工请求计入内部用电需求，防止太阳因电缓存满待机、加工又因待机不启动而互相等待。
- 检查物料、产物空间和可付电量后再推进；输出满或材料不足不扣电。已经支付的进度和在制产物持久化，拆坏后暂停，不能将进度和材料同时退回再重复加工。
- 配方声明确切的物品、输出和能耗，具体配方量留待平衡。不额外输出一份可再次回收的“全部反应热”，避免同一能量重复计入发电和加工收益。

这项需要独立配方/JEI/物流/结构插槽，工程量明显高于外观和告警，放在太阳发电首版稳定后做。暂不新增无用途的粒子、灰烬、等离子液或十几种中间物。

## 7. 整组升级与配置复制

一组采能翼由9块同级组件组成，手工逐块拆换容易漏块。建议后续在结构窗口加入“升级这一翼”：

- 先选中左/右/前/后翼，展示所需9个目标部件、返还旧部件，以及升级后的实际采能上限。
- 停机后执行，保留燃料、点火和端口设置。按真实放置/权限事件逐块处理；成功替换一块才扣一块材料，保护拒绝时停止，剩余材料留在玩家处，不吞旧方块。
- 如果中途只完成部分替换，装置提示该翼待完成，允许继续施工；不要假装所有世界事件都能完整回滚。
- 配置复制只复制负载、阈值、告警用途等设置，粘贴时逐项限幅，不复制库存、反应能量、点火资格或其他玩家的所有权。

## 工程范围与兼容

这些建议不增加新默认结构块，也不改变 [layout.json](art/solar-design/layout.json) 的220块默认蓝图；日冕加工仓是将来单独扩展的结构角色，其位置和数量在正式实现前另行定义。

首版建议纳入：按需调载、燃料回收、基础诊断/告警、视觉状态反馈。耀斑升载、日冕加工仓、批量升级、CC遥测分阶段实现，最终范围由用户确认。

所有外部访问沿用Mek安全模式、菜单距离/权限校验，服务端负责库存和能量事务。太阳核心停机/卸载后只保留数据，不继续产生任何离线收益。

## 核对与算量

- 本仓库 `ReactorMenu.access/clickMenuButton`、`Controller` 和 `Part` 提供现有权限、唯一预算、真实仓和暂停保存思路；太阳相关功能仍未实现。
- [CC:Tweaked 1.21.x peripheral](https://www.tweaked.cc/mc-1.21.x/module/peripheral.html)提供外设枚举、调用及连接/断开机制，可作为未来监控接口入口。此依据只证明有扩展方式，不代表本模组已有集成。
- 耀斑净收益按终极净功率×25%×600tick计算；燃料预算为原毛功率J×125%×115%×600tick。只核对数量关系，未验证游戏内平衡或管道吞吐。

本轮仅设计扩展，无新JAR、运行配方或已完成兼容承诺。
