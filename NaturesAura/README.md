# Nature's Mekanism

Minecraft 1.21.1 的自然灵气工业化扩展。机器使用 Mekanism 的升级、红石控制、六面配置、储能、物流和界面组件，直接读取 NaturesAura 配方。

![16×16 方块材质预览](art/block-preview.png)

## 安装

将构建产物 `build/libs/NaturesMekanism-0.1.8.jar` 放入客户端与服务端的 `mods` 目录，替换旧版扩展 JAR。新版包含此前的机器详细提示崩溃修复和旧版库存迁移。

本轮实际验证的依赖组合：

| 依赖 | 版本 |
| --- | --- |
| Java | 21 |
| Minecraft | 1.21.1 |
| NeoForge | 21.1.241 |
| Mekanism | 10.7.19.85 |
| Nature's Aura | 41.10 |
| Patchouli | 1.21-87-NEOFORGE |
| JEI（可选） | 19.22.1.316 |

不需要 Mekanism Generators。扩展开发时通过 Maven 下载依赖，不要求在相邻目录编译原模组。

## 机器

| 机器 | 输入与工作方式 | 结构 |
| --- | --- | --- |
| 通用灵气发生器 | 消耗 FE，生产可用加压管道输送的灵气；界面可开启环境释放 | 单方块 |
| 通用森林仪式 | 8 个材料输入槽；树苗、金叶粉使用“额外”槽；读取森林仪式配方 | 单方块 |
| 通用自然祭坛 | 原料、催化物、FE；优先使用罐内灵气，不足时从环境补足；催化物保留 | 单方块 |
| 通用呼唤仪式 | 供品、呼唤物、FE；一份呼唤物启动一批供品，最多 16 次配方 | 中央机器 + 原版花阵 |
| 灵气装瓶机 | 瓶与塞、FE；按维度和环境条件装瓶；支持模拟环境模块和目标选择 | 单方块 |
| 灵气调控器 | 用 FE 在储罐与环境之间回收或释放灵气，按上下限自动调节 | 单方块 |
| 通用降生祭坛 | 9 个通用原料槽，读取降生生物配方，消耗 FE 与灵气；可设置生成区域和数量上限 | 单方块 |
| 工业养殖机 | 9 个食物槽、成年配对动物与 FE；真实繁殖并收集原版降生之灵，支持普通繁殖模式 | 单方块 |

森林仪式和祭祀诸神的原版配方没有灵气消耗字段，这两台机器使用 FE。自然祭坛按原配方扣除灵气总量，速度升级不会改变每份配方的灵气总成本。

森林仪式默认每次额外消耗一棵符合配方的树苗和 16 份金叶粉，用于代替被原版仪式消耗的树与粉末布置；金叶粉数量可配置为 0。多个相同原料可放在同一个堆叠中，不必按原版基座拆开。

### 金叶无限模块

森林仪式机的 Mek 升级窗口下方新增一个独立模块槽，最多放入 **1 个金叶无限模块**。也可手持模块潜行右键机器安装；从模块槽取回即可卸载。

装入后不再需要专用额外槽中的金叶粉，默认总耗电变为 **2 倍**，该倍率叠加在 Mek 速度、能量升级计算之后，可通过 `infiniteGoldPowerMultiplier` 配置。树苗和配方材料仍然消耗，包括某些配方原料中的金叶；模块自身不消耗。处理中卸载模块会恢复金叶粉需求。

配方由强化合金、金叶和高级控制电路组成，可以在 JEI 中查询。

自然祭坛的左槽放原料，右侧输入槽放所需催化物。支持原版转化、粉碎催化物，以及加载配方定义的其他催化物。物品组件由原版 `Ingredient` 检查，例如末地灵气瓶不能用其他种类的瓶子替代。

## 装瓶机与模拟环境模块

输入原版的**瓶与塞**，接入 FE。默认每瓶需要 40 ticks、100 FE/t，支持 Mek 速度和能量升级。普通玻璃瓶不能代替瓶与塞。

未安装模块时，按钮在“自动 / 本地灵气 / 真空”之间切换，遵循原版半径 30 格的环境条件：

| 产物 | 条件 | 每瓶灵气成本 |
| --- | --- | --- |
| 瓶装阳光 | 主世界，环境灵气 ≥ 100,000 | 20,000 |
| 瓶装鬼魂 | 下界，环境灵气 ≥ 100,000 | 20,000 |
| 瓶装黑暗 | 末地，环境灵气 ≥ 100,000 | 20,000 |
| 瓶装真空 | 任意维度，环境灵气 ≤ -100,000 | 0 |

其他维度的本地灵气类型由 NaturesAura API 决定。“自动”根据实际环境选择本地灵气或真空；“本地灵气”和“真空”只生产指定类别。

灵气瓶优先使用内部储罐，不足部分从环境取得。环境门槛与资源成本分别检查：仅给储罐充灵气不能解除原版环境门槛。完整的 20,000 灵气在装瓶完成时扣除，避免刚好达到 100,000 的环境在加工途中跌破门槛。真空装瓶不会改变环境灵气，也不会消耗罐内灵气。

**模拟环境模块**的配方需要瓶装阳光、瓶装鬼魂、瓶装黑暗、瓶装真空各一份，以及 4 份强化合金和 1 个精英控制电路。配方检查瓶内类型，不能用重复的阳光瓶替代鬼魂或黑暗瓶。

模块最多安装 1 个，放入装瓶机升级窗口底部的独立槽，也可潜行右键安装。装入后可点击主界面按钮选择“阳光 / 鬼魂 / 黑暗 / 真空”，解除环境和维度门槛，默认总耗电翻倍；灵气瓶仍必须支付 20,000 灵气。模块取出后，已选的模拟目标会暂停；点击按钮可返回普通模式。选择、模块和加工进度会随存档保存，拆下机器也会保留选择和模块。

JEI 提供装瓶分类、各产物的原版条件和模块合成配方。

## 环境灵气调控

调控器默认把半径 16 格的环境灵气维持在 **1,200,000～2,200,000**：低于下限时释放储罐灵气，高于上限时回收进储罐，两者之间停止工作和耗电。回收与释放均为 1:1 转移，不会额外产生灵气。

主界面按钮依次切换“自动平衡 / 仅回收 / 仅释放 / 停用”。在上下限输入框中填写整数，按回车或点勾号应用；上方显示服务器确认的实际数值。允许 -1,000,000～100,000,000，且下限不能大于上限。负目标可用于维持真空装瓶需要的环境。

默认每个工作 tick 消耗 50 FE、最多转移 1,000 灵气，速度升级提高转移率。储罐满时不再回收，储罐空时不再释放；缺电时不改变任何灵气。数值、模式、库存和升级都会保存，拆下机器也会保留。

在升级窗口中最多放入 **4 个范围升级模块**，每个使调控半径增加 8 格，并额外增加一份正常耗电：1 个为 ×2，4 个为 ×5，倍率叠加在 Mek 升级计算之后。检测和调控不会主动加载远处区块。

Chemical 默认右侧输出，其余侧面输入，可改成输入、输出或输入/输出。接入管道即可把过量环境灵气供给其他机器，或从灵气发生器补充释放所需的储量。停用环境调控时，普通管道物流仍然工作。

原版灵气的扩散和平衡机制会继续影响实际读数；调控器依据实时值工作，不会冻结环境。

## 呼唤仪式的花阵

把原版 `naturesaura:offering_table` 换成通用呼唤仪式机，原来周围的花阵保持不变。检查来自原版 `OFFERING_TABLE` 结构的全部花朵位置，并接受 `minecraft:small_flowers` 标签中的花。

```text
  FFFFF
 F     F
F  FFF  F
F F   F F
F F M F F
F F   F F
F  FFF  F
 F     F
  FFFFF
```

`M` 是机器，`F` 是花；花和机器处在同一高度，花下面需要可种植的方块。布局沿用原版 9×9 花阵。

缺花时不扣 FE、不消耗物品；处理中拆花会暂停，补齐后继续。全部花位使用凋零玫瑰时，保留原版每批额外产生 4～8 个黑色染料的效果。

呼唤仪式对应“祭祀诸神”，产出物品。它不包含降生祭坛的生物召唤功能。

## 通用降生祭坛

将 JEI 中降生祭坛配方的原料放入左侧 3×3 槽，供给 FE 和灵气即可生成对应生物。直接读取当前配方表，支持数据包修改生物、原料、灵气量和时间；同种原料可以堆叠，带数量的 Ingredient 也会按数量扣除。

界面下方依次输入世界坐标轴 **X、Y、Z 偏移**，回车或点击勾号应用。默认偏移 `(0, 1, 0)`，即机器上方；陆生生物要有实心地面和足够空间，水生类别需要水。水平半径默认 2、基础最大 4；每个范围模块增加 2 格最大半径，最多 12 格。X/Z 偏移限 ±16，Y 限 ±8。不会强制加载目标区块。

数量上限默认 16，可设置为 1～128，统计区域水平范围内、中心高度上下 4 格的活生物，不统计玩家。达到上限、空间堵塞、红石暂停或缺少资源时停止耗电。生成进度保存到世界；其他模组取消生成后会保留完成进度，重试不重复消耗 FE。原料与灵气只在实际生成成功后扣除。

基础功耗由 `spawnerFEPerTick` 配置，默认 200 FE/t；Mek 速度与能量升级正常生效。优先用储罐灵气，不足部分从半径 35 格环境补足，牛配方仍为 50,000 灵气和基础 60 tick。范围模块沿用每个额外一份总功耗的规则。拆下机器保留范围、数量、库存、灵气和升级设置。

## 工业养殖机

把繁殖食物放入左侧 9 个输入槽，并在工作区域内饲养成年动物。机器每个周期给兼容的一对动物各用一份食物，要求距离小于 3 格、视线无遮挡，保留原版 6,000 tick 繁殖冷却。不会喂幼崽或抢用已由玩家喂入求偶状态的动物。美西螈吃完热带鱼桶后，输出槽返还水桶。

默认“降生之灵”模式要求亲本周围 30 格至少 **1,200,000 环境灵气**。由自然灵气的真实繁殖事件产出 1～3 个降生之灵，每个仍消耗原版 800 环境灵气，机器自动收集到右侧输出槽。可用灵气调控器维持环境；养殖机本身不设 Chemical 储罐。预留最大 3 个降生之灵的输出空间后才开始喂食加工。

点击模式按钮切换“普通繁殖”，可在较低灵气环境繁殖；达到灵气条件时仍遵循原版事件掉落。海龟和青蛙只在普通繁殖模式下工作，保留怀卵与后续产卵过程，不直接变出幼体或降生之灵。模组取消繁殖事件时，食物已用于喂食，亲本按原版进入冷却；该模组的事件优先级决定原版掉落是否已发生。

区域设置、数量上限和范围模块与通用降生祭坛相同。默认每对加工 **100 tick、200 FE/t**，可通过 `breederTicks`、`breederFEPerTick` 调整；Mek 速度/能量升级正常生效。每次收集一个掉落物实体另付一 tick 电量。只收集降生之灵，尊重拾取延迟和他人保留的物品归属，输出满或缺电时保留地上物品。机器模式、区域、库存、升级会随保存和拆卸保留。

## 灵气与自动化

推荐连接：电源 → 通用灵气发生器 → Mek 加压管道 → 通用自然祭坛。

扩展的 `naturesmekanism:aura` 是 Mek Chemical，1 单位对应 1 点 NaturesAura 灵气。发生器默认每 20 tick 消耗 8,000 FE、生产 2,000 灵气，未安装升级时平均为 400 FE/t 和 100 灵气/t。

产量会按储罐剩余空间缩减；即使剩余容量小于完整一批产量，也会继续填满，满罐后才停止耗电。输出一部分灵气后即可继续工作，无需清空储罐。

发生器默认仅向管道输出。开启“切换释放”后，还会从自己的储罐扣除灵气，写入周围真实的 NaturesAura 环境灵气，原模组装置可以正常使用。默认范围 16 格、释放上限 100 灵气/t、区域目标 2,000,000 灵气；达到目标或相邻区块未加载时暂停释放，不会强制加载区块。

通用自然祭坛既能使用管道送入储罐的灵气，也能直接使用周围环境灵气，默认检测范围 20 格。优先扣罐内灵气，仅从环境扣不足的部分；两者总消耗仍等于原配方的灵气需求。界面会单独显示“周围灵气”，内部储罐为空不代表机器无法工作。缺电、输出堵塞或可用灵气不足时不会提前消耗环境灵气，也不会将环境透支为负数。

默认侧面配置：

- FE：六面可输入。
- 物品：右侧输出，底部接入能量物品槽，其余侧面输入；可在 Mek 侧面配置窗口调整。
- 森林仪式机：背面默认设为“额外”，只接收树苗和金叶粉；普通“输入”和“输入/输出”不包含这两个槽。旧机器保留原侧面设置，更新后可将需要的一面改为“额外”。
- Chemical：发生器六面输出，自然祭坛、装瓶机和降生祭坛六面输入。
- 调控器的 Chemical 默认右侧输出、其余侧面输入；支持双向配置。
- 机器默认自动输出；支持 Mek 速度、能量升级和红石控制。

处理中断电、灵气不足或输出堵塞时暂停。区块/世界保存可恢复加工进度。拆下机器保留库存、储能、灵气、升级和侧面设置；正在执行的加工会重新开始，已经用于这段加工的 FE/灵气不退回。

## 配置与开发

数值位于世界的服务端配置文件 `serverconfig/naturesmekanism-server.toml`。可调整加工机的基础 FE/t、发生器的 FE/t 与每周期产量、呼唤仪式时长、森林仪式金叶粉数量、金叶无限模块耗电倍率、环境释放速率和目标上限，以及自然祭坛的环境检测范围 `altarEnvironmentRadius`。装瓶机新增 `bottlerFEPerTick`、`bottlerTicks`、`simulationPowerMultiplier`；每瓶灵气成本和原版环境门槛保持原值。修改基础功耗后建议重新加载世界。

在此目录用 PowerShell 7 执行：

```powershell
$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-home'
.\gradlew.bat build
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
```

JSON 资源由 `python tools/generate_resources.py` 生成。八台机器使用新增的 16×16 方块贴图，参考原版 Mek 的灰黑工业风格，包含正面、顶部、侧面和工作状态正面。贴图原稿、完整提示词和导出说明见 [材质说明](art/README.md)。JEI 可显示对应的原版配方与机器说明。

自动验证包含 7 项单元测试和 48 项服务端 GameTest，覆盖真实加压管道、环境灵气、配方和催化物、资源不足、存档恢复、机器掉落及库存提示读取、旧版库存迁移、模块拆装和功耗、中英文界面标题、装瓶与环境调控边界，以及实际生物生成、数量限制、事件取消、配方重载、区域保存、原版繁殖与怀卵、降生之灵产出和物品拾取。客户端游戏内验收由使用者进行。
