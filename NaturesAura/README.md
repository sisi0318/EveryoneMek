# Nature's Mekanism

Minecraft 1.21.1 的自然灵气工业化扩展。机器使用 Mekanism 的升级、红石控制、六面配置、储能、物流和界面组件，直接读取 NaturesAura 配方。

![16×16 方块材质预览](art/block-preview.png)

## 安装

将构建产物 `build/libs/NaturesMekanism-0.1.3.jar` 放入客户端与服务端的 `mods` 目录，替换旧版扩展 JAR。

本轮实际验证的依赖组合：

| 依赖 | 版本 |
| --- | --- |
| Java | 21 |
| Minecraft | 1.21.1 |
| NeoForge | 21.1.241 |
| Mekanism | 10.7.19.85 |
| Nature's Aura | 41.10 |
| Patchouli | 1.21-87-NEOFORGE |
| JEI（可选） | 19.22.1.316 |

不需要 Mekanism Generators。扩展开发时通过 Maven 下载依赖，不要求在相邻目录编译原模组。

## 四台机器

| 机器 | 输入与工作方式 | 结构 |
| --- | --- | --- |
| 通用灵气发生器 | 消耗 FE，生产可用加压管道输送的灵气；界面可开启环境释放 | 单方块 |
| 通用森林仪式 | 8 个材料输入槽；树苗、金叶粉使用“额外”槽；读取森林仪式配方 | 单方块 |
| 通用自然祭坛 | 原料、催化物、FE；优先使用罐内灵气，不足时从环境补足；催化物保留 | 单方块 |
| 通用呼唤仪式 | 供品、呼唤物、FE；一份呼唤物启动一批供品，最多 16 次配方 | 中央机器 + 原版花阵 |

森林仪式和祭祀诸神的原版配方没有灵气消耗字段，这两台机器使用 FE。自然祭坛按原配方扣除灵气总量，速度升级不会改变每份配方的灵气总成本。

森林仪式默认每次额外消耗一棵符合配方的树苗和 16 份金叶粉，用于代替被原版仪式消耗的树与粉末布置；金叶粉数量可配置为 0。多个相同原料可放在同一个堆叠中，不必按原版基座拆开。

### 金叶无限模块

森林仪式机的 Mek 升级窗口下方新增一个独立模块槽，最多放入 **1 个金叶无限模块**。也可手持模块潜行右键机器安装；从模块槽取回即可卸载。

装入后不再需要专用额外槽中的金叶粉，默认总耗电变为 **2 倍**，该倍率叠加在 Mek 速度、能量升级计算之后，可通过 `infiniteGoldPowerMultiplier` 配置。树苗和配方材料仍然消耗，包括某些配方原料中的金叶；模块自身不消耗。处理中卸载模块会恢复金叶粉需求。

配方由强化合金、金叶和高级控制电路组成，可以在 JEI 中查询。

自然祭坛的左槽放原料，右侧输入槽放所需催化物。支持原版转化、粉碎催化物，以及加载配方定义的其他催化物。物品组件由原版 `Ingredient` 检查，例如末地灵气瓶不能用其他种类的瓶子替代。

## 呼唤仪式的花阵

把原版 `naturesaura:offering_table` 换成通用呼唤仪式机，原来周围的花阵保持不变。检查来自原版 `OFFERING_TABLE` 结构的全部花朵位置，并接受 `minecraft:small_flowers` 标签中的花。

```text
  FFFFF
 F     F
F  FFF  F
F F   F F
F F M F F
F F   F F
F  FFF  F
 F     F
  FFFFF
```

`M` 是机器，`F` 是花；花和机器处在同一高度，花下面需要可种植的方块。布局沿用原版 9×9 花阵。

缺花时不扣 FE、不消耗物品；处理中拆花会暂停，补齐后继续。全部花位使用凋零玫瑰时，保留原版每批额外产生 4～8 个黑色染料的效果。

呼唤仪式对应“祭祀诸神”，产出物品。它不包含降生祭坛的生物召唤功能。

## 灵气与自动化

推荐连接：电源 → 通用灵气发生器 → Mek 加压管道 → 通用自然祭坛。

扩展的 `naturesmekanism:aura` 是 Mek Chemical，1 单位对应 1 点 NaturesAura 灵气。发生器默认每 20 tick 消耗 8,000 FE、生产 2,000 灵气，未安装升级时平均为 400 FE/t 和 100 灵气/t。

产量会按储罐剩余空间缩减；即使剩余容量小于完整一批产量，也会继续填满，满罐后才停止耗电。输出一部分灵气后即可继续工作，无需清空储罐。

发生器默认仅向管道输出。开启“切换释放”后，还会从自己的储罐扣除灵气，写入周围真实的 NaturesAura 环境灵气，原模组装置可以正常使用。默认范围 16 格、释放上限 100 灵气/t、区域目标 2,000,000 灵气；达到目标或相邻区块未加载时暂停释放，不会强制加载区块。

通用自然祭坛既能使用管道送入储罐的灵气，也能直接使用周围环境灵气，默认检测范围 20 格。优先扣罐内灵气，仅从环境扣不足的部分；两者总消耗仍等于原配方的灵气需求。界面会单独显示“周围灵气”，内部储罐为空不代表机器无法工作。缺电、输出堵塞或可用灵气不足时不会提前消耗环境灵气，也不会将环境透支为负数。

默认侧面配置：

- FE：六面可输入。
- 物品：右侧输出，底部接入能量物品槽，其余侧面输入；可在 Mek 侧面配置窗口调整。
- 森林仪式机：背面默认设为“额外”，只接收树苗和金叶粉；普通“输入”和“输入/输出”不包含这两个槽。旧机器保留原侧面设置，更新后可将需要的一面改为“额外”。
- Chemical：发生器六面输出，自然祭坛六面输入。
- 机器默认自动输出；支持 Mek 速度、能量升级和红石控制。

处理中断电、灵气不足或输出堵塞时暂停。区块/世界保存可恢复加工进度。拆下机器保留库存、储能、灵气、升级和侧面设置；正在执行的加工会重新开始，已经用于这段加工的 FE/灵气不退回。

## 配置与开发

数值位于世界的服务端配置文件 `serverconfig/naturesmekanism-server.toml`。可调整三种加工机的基础 FE/t、发生器的 FE/t 与每周期产量、呼唤仪式时长、森林仪式金叶粉数量、金叶无限模块耗电倍率、环境释放速率和目标上限，以及自然祭坛的环境检测范围 `altarEnvironmentRadius`。修改基础功耗后建议重新加载世界。

在此目录用 PowerShell 7 执行：

```powershell
$env:GRADLE_USER_HOME = Join-Path $PWD '.gradle-home'
.\gradlew.bat build
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
```

JSON 资源由 `python tools/generate_resources.py` 生成。四台机器使用新增的 16×16 方块贴图，参考原版 Mek 的灰黑工业风格，包含正面、顶部、侧面和工作状态正面。贴图原稿、完整提示词和导出说明见 [材质说明](art/README.md)。JEI 可显示这三台加工机对应的原版配方与机器说明。

目前已通过构建、6 项单元测试和 19 项服务端 GameTest，覆盖真实加压管道、环境灵气、三种配方、催化物、满输出、存档恢复、机器掉落组件、高速部分产量、额外输入分离、模块拆装/功耗/保存、中英文界面标题，以及自然祭坛环境供能、混合供能和暂停恢复。客户端游戏内验收由使用者进行。
